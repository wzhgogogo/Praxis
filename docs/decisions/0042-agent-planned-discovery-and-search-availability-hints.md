## Context

当前 Planner 将第一个正向 HARD 原文机械投影为关键词。已暴露真实语义包含
`kaiseki restaurant`、`tempura restaurant`、`local food`；它们和来源的有效类别未必一致。
当前类别扩展发生在首批调查之后，而且与选地区共用页数。一次空检索可能在改写之前就结束来源。
历史检索词实验要求模型逐字引用空状态，回放不能稳定满足，不能作为本设计的空结果证明。

本 ADR 只提出两个分开测量的变化：先让 Agent 规划检索，再增加查位请求的搜索筛选线索。
基线输入取最近 Live 的实际语义与地点上下文，只按批准变体移日期，不用 Gold 替换实际条件。
基线发现探测及其失败、未到达来源以链接报告为准；探测不是查位、交付或改进后验收。

## Decision

### 1. 来源顺序与检索表达式分工

Planner 继续按权威 intent、地点与来源能力决定来源顺序，将全部正向条件（文本、强度、稳定的
`criterionRef`）交给检索决策。Agent 选择短关键词、当前观察到的类别入口、两者组合，或明确不加
关键词的通用列表。共享代码不按站点、地名、菜系或用例分支，不维护同义词或菜系映射表。

尚无页面可观察、必须先有文本才能进入的来源，在已有决策中提供检索选择；必要时每次请求最多
增加一次规划模型调用，仍计入共享预算。目录型来源先按 ADR-0040 观察并选地区，再根据地区页面
的实际类别和结果选择检索。Agent 决策不得直接修改 Task State 或执行来源请求。

### 2. 执行器核对表达式

关键词最多三个词，绑定一个正向条件；拒绝数字、请求地点名、日期、时间文字，以及负向条件、
价格、人数和时间条件的检索用途。核对格式和条件引用，不把它升级为候选满足该条件的证据。
不合格时记录拒绝原因，使用不加关键词的通用列表或已观察且合规的类别，不添加另一套猜词机制。

类别链接必须在当前快照中可见，且与已选择地区属于同一列表根；继续执行 ADR-0040 的地区核对。
移除旧关键词用页面自己的筛选移除入口或来源 Pack 的语法，不拼接模型猜测的地区 URL。
地点、日期、时间、人数由执行器从权威值填入，模型不能改写。

### 3. 详情前的有界改写与空状态

选定地区后，解析结果少于一批五家，或页面有明确空状态时，可以在读详情前改写。
每个来源最多两次改写，Agent 可换词、选类别、组合或不检索。已观察到的匹配结果保留在队列前面，
改写不清空已读进度、模型额度或时钟。解析器和页面明确空状态共同识别无结果，不要求模型逐字引用。
解析失败、加载中、未观察到结果仍为未知，不冒充明确空状态。

用完改写额度后调查已有候选或如实结束当前批次；一次空检索不表示来源穷尽，更不表示所有门店无位。
退役当前“首批查完后才允许一次类别扩展”的路径、旧调用方和对应实现测试，不保留双轨兼容。

### 4. 来源预算

采用分开计数：地区/入口导航最多四页，检索结果最多三页（初次加两次改写），合计最多七个列表文档。
地区纠正仍受 ADR-0040 的一次换入口规则限制；同一文档既是地区落点又是检索结果时只记一个实际页，
同时消耗相应分类额度。页数按实际导航累计，重新访问也计入，不能靠切换类别重置。
详情批次仍按现有五家及既有详情上限，不扩大候选资格或第二批范围。

这是对旧共用六页上限的有意调整，目的是让地区落地之后仍有初次检索与两次改写的明确空间。
来源已有时间上限（原生发现九十秒）不提高；全局五百秒、五十次模型调用不提高。
规划、地区选择、改写、筛选与详情共用原有模型计数和剩余时限，达到任何上限就停止该操作并留诊断。
第一段探测仍是十五调用/一百八十秒，不能以本提案增加其额度。

### 5. 搜索级空位筛选仅提供线索

只对 AVAILABILITY 且有权威日期和人数的请求应用。推荐目标保持原路径。
选择 Pack 自有 URL 语法，减少重复控件操作；来源差异只留在来源包，不进入共享执行器。
拟使用的公开参数为：Tabelog 的 `vac_net`、`svd`、`svt`、`svps`；TableCheck 的
`date`、`time`、`num_people`、`availability_mode`。来源语法不能表达请求时间窗时跳过该筛选，
不把时间窗缩成另一个请求，不修改用户意图。

导航后必须观察页面所选日期、人数及适用的时段，核对与权威请求一致才标为已应用。
无法核对、值冲突或筛选明确为空时，回退未加筛选列表，记录原因；仍消耗原预算，不无限重试。
卡片时段仅作调查排序线索，不创建可交付 Offer、空位证据、来源穷尽或“无位”结论。
交付仍逐家走原门店日历、身份和证据规则。

实施时同步 Pack 已审核读取规则、Recorder 安全参数表、外层 `reviewed-reads.json`；逐项列出新增形状
供独立复核。Guard 拒绝其他未审核参数。ADR-0036 其余边界不变，不增加登录、表单提交、点击时段、
预约、支付或个人信息操作；本阶段不打开预订表单。

### 6. 不变的合同与验收顺序

HARD 资格、来源身份、精确坐标半径、新鲜度、权威日期人数、语义目标、Gold 和 Evaluator 不变。
检索只改变找到谁，不能决定谁合格。ADR-0040 的已观察地区入口、一次纠正和坐标兜底继续有效。
本 ADR 获批后才部分替代 ADR-0037 决定 2–3 的表达式生成方式；来源顺序和 Pack 职责继续有效。

获批后先实施 P2-1a 并跑相同十次探测检查点 A，再实施 P2-1b 并跑检查点 B。
每次只比较一个变量，输入、中心、见证、预算和模型配置固定；过期见证先重认证。
真实模型调用及每次改写/未到达来源独立记录，连续两轮无提升按 Playbook 停止，不自动扩大预算。
基线与历史卡点明显不同或出现 S0 时先停下报告，不能用未完成分母宣称通过。

离线先红后绿覆盖稀疏转类别、空结果改写、额度耗尽、越地区类别、非法关键词、推荐不变和预算；
真实 Chromium 动态 Fixture 验证类别入口与明确空状态。搜索筛选另覆盖应用/失配/空结果回退、
权威值不可改写、Recorder 忠实保存和 Guard 误放行反例。代码五门禁按 Test Skill 执行。
检查点 B 与独立复核允许进入后，才进行第七项完整 Live；第一段不启动完整 Live。

## Consequences

新增的是当前请求的有界检索决策及其审计事实，不是可任意执行 URL 的通用规划框架。
可能增加少量模型调用和列表页，必须在原时间与调用总额内换取更有效候选；A/B 检查点分别验证增量。
来源当前页面不提供所需类别或筛选时如实保留限制，不能推导为不存在合格餐厅。
本文件 Accepted 表示决策已获批准，不表示上述能力已完成网站验证；当前实现与证据以 STATUS 及批次报告为准。

## Alternatives considered

- 保留 HARD 原文机械投影并增加菜系映射：缺少通用依据，违反不写死原则。
- 继续要求模型逐字引用空结果：历史实验已暴露接受性问题，改用来源解析与明确空状态。
- 把卡片时段当交付空位：会改变证据与资格规则，拒绝。
- 一次实施检索与筛选后只跑完整 Live：不能隔离增量，拒绝；保留 A/B 探测。
