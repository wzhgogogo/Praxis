## 2 已确定的决定（2026-10-12 至 10-16，用户确认）

1. **顺序：** P2-0 → T1 → E1（已完成）→ 找店改进。预约与前端在另一条线并行，两条线在 Web 文件和"推荐／查位"口径上要相互通知。
2. **评测口径：** 按 Eval Skill（当前 2.7）与 `.eval-artifacts/calibration-phase1-20261015/labeling-rules.md` 的 R1–R9 执行，其中：
   - 结果类型按用户实际得到的结果判定；
   - 每个条件都有"满足／不满足／未核对"状态；
   - S0 分为声明与越界两项，均零容忍。
3. **措辞等价：** 用审核过的等价表，不用模型评判。新出现的措辞对，由用户逐对确认后加入。
4. **样本：** 用于判断改进或退步的 Live 结论，每个关键用例每个检查点至少 3 次；只跑 1 次的写明"单次诊断"。
5. **无结果补见证：** 每次 0 交付的 Live，外层脚本立即对已登记见证店做一次四参数只读 GET。
6. **推荐／查位的目标边界：** 暂缓（Phase 1 Playbook 附录 D 第五组第 2 项）。本阶段不改语义 Prompt 的目标定义。
7. **不写死：** 不为 h001 或任何单个用例写专用规则。验收看同一类卡点的全部用例。

## 3 实施原则

- **Agent 负责判断，代码负责核对。** 检索词、类别、地区和候选选择由 Agent 根据页面上观察到的内容决定；HARD 条件、请求绑定和交付资格由代码按页面事实核对（沿用 ADR-0025、ADR-0037、ADR-0040 的方向）。
- **先离线，后 Live。** 每项改动先在回放（决策种子）和固定来源上做成对比较，有提升才进入 Live；Live 用于确认真实网站上的效果，并发现新的失败。
- **一次只改一个变量。** 比较前写明唯一的变化，固定 Gold、日期规则、预算和模型配置。
- **复核者独立复跑。** 每批的门禁和评测由复核者在独立环境复跑；不能复跑的部分在报告中写明。
- 新增或修改来源 Adapter 时，同步 Capability Matrix 和 Harness 场景（AGENTS.md）。

## 6 退出条件（全部满足）

阈值已由用户确认（第 9 节）。"尽量交付 3 家"不是退出条件，只作为指标记录（每次交付的店数分布）。

1. **找得到（开发集）：** h001（明日或指定日期变体）、KF-H005、神乐坂、吉祥寺四例，每例 3 次中至少 2 次 QUALIFIED_DELIVERY（运行前后见证有效）。
2. **泛化（留出集）：** 至少 6 例中，至少 4 例每例 3 次中至少 2 次 QUALIFIED_DELIVERY；其余没有交付的，第一卡点不得属于本阶段工作包。
3. **安全：** 本阶段全部运行 S0-声明为 0；新运行的 S0-越界都能评价（外层请求体核对生效），且为 0。
4. **说得清：** 每次交付对每个条件都给出满足／不满足／未核对，评测器核对与展示一致；软偏好不满足时如实告知，不被当作满足。
5. **耗时（2026-10-19 起只作为指标）：** 有交付的运行，报告中位数和最长耗时，目标仍为中位数 ≤ 180 秒、最长 ≤ 300 秒（目前约 130–430 秒）。用户决定：耗时不作为退出门槛；如果只有耗时未达目标，第二阶段照常结束，耗时作为第三阶段的第一项。
6. **通用性：** 共享层没有新增站点、地名、菜系或评测坐标常量；站点专用代码总行数没有净增加。

## 7 预算与停止规则

估算：每次 Live 约 25–47 次模型调用。

| 项目 | 上限（用户已批准） |
| --- | --- |
| P2-1 | 开发集 4 例 × 3 次 × 2 个检查点 = 24 次。2026-10-17 用户批准探测从 30 次追加到 40 次（重跑基线）。2026-10-16 细化：改动前基线和中间检查点改用只跑找店阶段的探测（3 个检查点 × 10 次，每次 ≤ 15 次模型调用，不计入 Live 次数，计入模型调用）；Live 在改动后跑 12 次，另 12 次为备用，需复核者同意 |
| P2-2、P2-3 | 各 ≤ 24 次 |
| 留出集退出检查 | 6 例 × 3 次 = 18 次 |
| 环境失败重跑 | 另计，每例最多 1 次，合计 ≤ 10 次 |
| 整单 Live 合计 | ≤ 100 次；每次 500 秒、50 次模型调用、40 次 Google 请求（沿用） |
| 模型调用合计 | Live 与回放共 ≤ 4,000 次（第一阶段用掉 1,086 次） |
| 见证认证与复查 | 不调用模型；只读公开页面和四参数 GET，不打开预订表单 |

停止规则：

- 出现 S0（声明或越界）：立即停止该批剩余运行，先修复。
- 同一项改进在回放或固定来源上连续 2 轮没有提升：停止该项，带证据请用户决定。
- 只有 ENV_FAILURE 和 ORCHESTRATION_INTERRUPTED 可以重跑，每例最多 1 次。
- 不自动扩大预算，不放宽门槛；需要调整时由用户批准并写入本文件。
