本轮以完整 H001 交付为目标：在正常原生发现的候选中，处理来源要求的查询前置选项，补齐必要 HARD 事实，并在 **500 秒、全部模型调用合计 50 次以内，实际展示至少一个独立核验合格的结果**。查位采用单来源 45 秒、单候选 60 秒；其他额度先保持，修复实际接线后再依据有效进展调整。

本文件是后续实施计划。编写计划不代表代码已实现、ADR 已接受或新的真实调用已获授权。执行时复用会话中已有授权及其预算；不得把环境开关或历史某轮授权当作无限重跑许可。

## 1 交付切片与完成条件

完整链路为：用户请求 → 原生发现 → 必要事实与查位调查 → 证据接纳 → Runtime 实际执行 PRESENT_RESULTS。事实与查位可以按已有合法动作采用不同顺序；不人为规定每店必须先查事实或先查位。

合格结果同时满足：

1. 来自本轮正常发现，门店归属与地点符合权威请求。
2. HARD 条件有当前、可追溯、适用范围正确的事实支持。
3. 日期、人数、时间窗与来源实际选中状态一致，库存属于同门店及适用服务类别。
4. 库存未过期，最终展示引用能够独立重建。
5. 运行内真实发生 PRESENT_RESULTS；从失败产物中手工挑出一个候选不算交付。

保持默认结果目标三家及已有短批规则：当前来源的当前有界批次完成适用调查后，按 ADR-0033 可展示已有一至两家合格结果，记录目标缺口，不为凑三家继续消耗下一分块。用户明确要求的数量仍须满足原合同。全局交付窗口沿用 ADR-0031，不用任意“找到一家就结束”替代既有条件。

离线机制完成、固定来源真实模型通过、完整 Live 交付分别签收。Live 没有合格库存时，可以证明调查或安全收尾，但本轮“实际交付合格结果”目标仍未完成；不扩大地点、改时间、放宽 HARD 或指定一家店制造通过。

## 3 保持的边界与最小决策调整

冻结 Semantic Prompt、Schema、Compiler、H001 Gold、HARD 强度、人数和时间解释、现有地点核验及新鲜度规则。保留 Tabelog → TableCheck 的原生发现顺序、来源内正常排序与续查；原生候选只在所属预约平台查位，不反查另一平台的同一家店。

共享浏览器层负责控件、观察版本、受控动作和后置回读；来源 Adapter 负责字段含义、查询作用、门店连续性及库存解释；Restaurant Domain 负责条件适用范围和展示资格。模型仍只提议动作或给出带引用的事实判断，经现有校验和 Runtime 接纳，不直接生成权威状态或外部写操作。

### 实施前需明确的 ADR

ADR-0032 当前明确规定“原生候选只能进入其所属平台的事实与查位读取”。同平台菜单追查符合该决策；跟进官网补证超出其现有边界。新增窄 ADR，明确允许从已确认门店的详情页实际观察到的相关外链，读取可证明适用于该门店的公开事实；查位来源策略不变。链接只是线索，不能自动赋予目标网站 HIGH 身份。

同一切片应显式记录 500 秒是新的开发验收预算，以及它对 ADR-0031 中历史 300 秒额度表述的适用调整；45 秒交付窗口及其条件保留。不得原地改写 Accepted ADR 或历史运行预算。无需另建来源路由、实体合并或通用预算调度架构。

新增单选属于共享浏览器原语；证据范围扩展用于防止错误成功，只实现当前闭环需要的最小结构。普通来源没有服务分区时，不强制新增类别 ID；不构建通用表单 DSL、套餐目录、跨站类别本体或未知网站爬虫。

## 4 预算及生效范围

### 下一轮明确使用的配置

| 额度 | 目标值 | 计量范围与处理 |
| --- | --- | --- |
| 整单墙钟时间 | 500 秒 | 从语义理解前开始，覆盖发现、事实、查位和实际展示；业务日期时钟独立 |
| 全部模型调用 | 50 次 | 语义、补充解释、Agent、浏览器决策、事实判断的实际调用均累计，失败调用也计入 |
| 单候选查位 | 60 秒 | 同一次候选查位的执行累计，不因打开新页面重置 |
| 单来源查位 | 45 秒 | 含来源会话建立、导航、观察、决策、操作和结果等待；同时服从剩余候选及整单时间 |
| 查位浏览器决策 | 单候选 20 次 | 保持现有调试配置，同时受整单 50 次约束 |
| 查位及原生发现的局部浏览器操作 | 30 次 | 保持上轮显式配置；按现有 executor 计量单位，发现按当前工作分块计数，不称全局 30 次 |
| Agent 循环 | 30 步 | 保持；与浏览器内部决策次数分别记录 |
| 业务 Agent 连续拒绝 | 最多 5 次 | 同一被拒动作重复仍提前停止；浏览器两次相同无进展提议的停止规则保持 |
| 原生发现 | 每来源累计 90 秒、10 次详情尝试，每分块 5 次 | 延续持久进度和 pending-first，不按 500/300 比例放大 |
| 结构化单次读取 | 30 秒 | 保持；受父级剩余期限约束 |
| 其他已执行来源配额 | 保持 | 包括现有会话、匹配及页面限制，不增加备用来源或自动重试 |

原生查位只使用候选所属平台，不能将 60−45 的 15 秒解释为保证分配给另一预约平台。各上限也不是预留时长：实际可用时间是所有适用剩余额度的最小值，不需要把 500 秒固定切成若干阶段。

### 事实调查的独立预算

当前 Google 网站事实路径配置为：浏览器段累计 45 秒、单来源 30 秒、每候选最多 4 次浏览器模型决策和 24 次浏览器操作。Google 前置读取与最终事实判断不属于这 45 秒；最终事实判断当前另有 8 秒请求超时，且计入整单 50 次调用。不能把现状写成“整个事实动作 45 秒”。

原生事实路径当前直接开会话、导航、快照和判断，尚未采用上述 executor 局部额度。本切片将必要追查接入现有受控执行器，起始复用 45/30 秒、4 次浏览器决策、24 次操作，作为新增接线目标：

- 浏览器段从本候选的执行器／会话建立开始，到最后一次有效页面回读结束，导航、观察、浏览器决策、动作与等待都计入。
- 同一候选的详情、菜单、套餐及允许的官网后续读取累计消耗浏览器段额度；换页不重置。不同允许来源仍共享该浏览器段累计期限。
- 整个事实动作包括最后的事实判断，继续受 Router、父级整单 deadline 和统一模型计数约束；不额外发放一份全局调用预算。
- 先验证在起始配额内完成已知可行场景。只有有效追查被明确截止时，才讨论调整对应局部值，不自动把所有网络和模型超时提高。

### 必须修复的预算接线

1. 原生固定来源 Runner 的 CLI 目前仍限制 300 秒；放宽到目标额度，同时显式传入候选、来源、操作和模型限制。只改 CLI 上限不够：该入口目前仍可能使用 executor 的 6 次浏览器决策、24 次操作等默认值。
2. 固定来源、Live 及用于同等验收的 Web 入口复用现有 composition 参数和已解析运行配置。让 artifact 同时记录目标配置与实际生效范围；只为对齐接线做小改动，不重写全部配置系统。
3. Live Runner 目前可接受 500 秒参数，但共享默认墙钟上限仍是 20 分钟、整单模型默认上限是 150 次；不能用默认启动方式声称运行符合 500/50。用于比较的 Web 同样必须取得整单模型计数和从语义前开始的截止，而非仅限制浏览器调用。
4. 浏览器全局默认 120 次不能替代整单 50 次；在本轮更紧外层限制下它不是新增额度。maxAvailabilityReads=20 与 maxBrowserRuntimeFallbacks=1 当前仅声明、未发现执行接线，不能报告为已执行门禁，也不为凑齐预算表新增机制。
5. 到期或取消后不再发起外部读取及模型调用；会话关闭和产物收束单独记录。若收束越过任务期限，如实报告，不用移动起点或暂停计时制造合规。

## 6 通用查询前置选项

### 观察和操作

共享控件合同补齐当前来源及受控对照实际需要的单选语义：组选项归属、字段／组标签、选项 ID 或值、标签、选中态、禁用态及当前观察引用。原生 radio 和来源实际使用的 ARIA 单选需正确归一化；不把 radio 当普通文本 INPUT，也不假设所有页面控件都有原生 form。

动作表达“在此组选择此项”，执行时复查目标身份、可见性、禁用状态和所属组。沿用现有观察版本、动作校验与后置读回；checkbox 的可取消语义不直接照搬给 radio。不提供任意 CSS、脚本、URL 或绕过许可的普通 CLICK。

### 来源许可与选择依据

来源 Adapter 根据已确认的页面结构和字段作用，只对影响公开查询的选项提供正向许可。不能按 HTTP GET、radio 标签或文字里出现 Sushi 就认定安全。来源语义允许平台专属字段解析，但禁止按 Bellwood、Omo 等店名或来源实体 ID 分支。

选择依据来自权威用户条件和实际页面说明：存在明确相容选项时由 Agent 完成；不能默认选第一项。多个相容查询选项按当前页面证据在原预算内调查，不新增全组合枚举。选项仅用于查看公开价格／套餐信息，与实际接受收费套餐或条款承诺分别判断；存在重要偏好歧义或承诺时才请求用户决策，来源失败不自动变成澄清问题。

### 请求及证据范围

在现有查询上下文、原始观察、事实引用和库存证据中，保存最小来源服务范围：所属门店、来源字段／组、选项 ID 或值及标签、含义依据、实际选中读回与对应结果。精确字段名在现有 Contract 中统一，不另造 Semantic 用户字段。

接纳规则必须进入 Grounding、展示资格和独立 Evaluator：

- 门店整体事实可用于适用的服务；只针对某类别的事实只能支持该类别库存。
- 类别选择后的日期、人数和时间可能重置，旧库存也可能短暂保留。必须同时确认类别选中、完整请求生效和结果属于这次查询，不能只检查 radio=true。
- 新查询后旧类别结果及迟到响应不能形成新 Offer；利用已有请求关联和响应时序，不为每次操作加入固定长等待。
- 某类别的无位结论只适用于该范围，不能扩大为整店无位；仍有相容合法选项时按现有预算调查，未查范围保持未知。
- 没有服务分区的来源保留正常门店级证据；只有来源实际区分事实／库存时才要求范围对应。需要类别对应却无法确认时保持 UNKNOWN。
- 来源服务类别与 ADR-0030 的负向餐厅类型规则分别处理。选寿司区不自动消除用户对整店类型的排除；保留原 Criterion 语义，不通过新字段放宽 HARD。

类别相关事实判断只能引用原始片段并保留其适用范围；模型宣称“这项相容”本身不成为库存或事实证据。类别范围需进入必要的 Offer 关联，避免同店同时间的不同服务库存互相覆盖。若持久 State／Contract 语义不兼容，按仓库规则更新版本及所有调用方，Pilot 前不保留双路径。

## 7 围绕缺失 HARD 的事实追查

一次 INVESTIGATE_CANDIDATE_FACTS 行动内部完成以下过程，复用现有浏览器和事实判断能力：

1. 从当前候选和权威请求识别尚缺支持的具体条件，消费仍有效、适用范围正确的已有事实。
2. 读取同源详情，优先检查页面已提供、与缺口相关的菜单／套餐入口。已有充分证据时不扩大阅读。
3. 同源仍缺必要事实，且存在可追溯归属的相关外链时，在新增 ADR 允许范围内跟进官网。不是每家必须读官网，也不猜 URL 或强制回到 Google 匹配。
4. 保留页面来源、观察时间、归属证据、最小相关原文引用和适用门店／服务范围，交给已有事实判断与接纳链。
5. 得到支持、冲突或仍未知后，保存这次调查结果及真实停止原因，再回到正常 Agent 流程。

阅读结束与 HARD 被支持是不同状态。Sushi、Restaurant、Wine Bar 或“有寿司套餐”不能自动证明 omakase；hasRequestedFacts 不能仅凭任意类型事实非空就提前结束。复用当前缺失条件评估及事实判断，只有新的相关证据可能改变决定时才需要新的判断，不在每次导航、点击或快照后机械增加模型调用。

保留 FACTS_ALREADY_CHECKED 等既有防重复边界；通过同一次调查内的 continuation 补追查，不通过放开 UNKNOWN 任意重查实现。调查停止后若有其他候选合法动作则继续，不强制把某店修成合格结果。

| 本次调查遇到的状态 | 处理 |
| --- | --- |
| 缺失条件已有充分、适用支持 | 结束必要阅读，进入正常接纳及后续查位／展示 |
| 明确冲突，当前结果不合格 | 记录适用范围和依据，结束无价值追查 |
| 未读的相关入口存在且尚有预算 | 在同一次调查内继续，不重复同一介绍页 |
| 相关入口已读完、无入口或无新证据 | 保留 UNKNOWN，说明未证实的条件和调查范围 |
| 网站归属不清、访问失败、预算截止 | 保留实际原因，不伪装成“不提供”或“查遍全网” |

外链指向品牌网站不自动证明某菜单适用于当前分店；原平台的 HIGH 身份也不自动借给外站。只补当前门店归属所需证据，保留已有身份准则，不新增通用实体合并。

如果实际菜单仅有当前无法读取的格式，先记录具体阻断及最小验证方法。不得自动扩成 PDF／OCR／截图多 Provider 兜底工程；也不得仅因访问失败把浏览能力从目标中移除。

## 8 日期与观察效率

当前 Tabelog 已区分 UNOBSERVED 与 CLOSED／FULL／PHONE_ONLY，拒绝未完成的 COMPLETE 后也会重新观察。复用这些行为，围绕 Teppen、Ajuuta 的具体证据做补强。

| 证据状态 | 下一步 |
| --- | --- |
| 目标未展开、控件未进入观察或观察被截断 | 通过已观察的合法展开／日历动作取得相关控件，再决定 |
| 已确认目标日期明确受限或 disabled | 拒绝非法操作，记录来源范围内结论；不通过翻到错误月份逃避限制 |
| 模型提议错误日期／月份 | 拒绝动作并给出可恢复反馈；正常后续动作仍应在原预算完成 |
| 操作完成但结果尚在更新 | 利用相关结果变化和已有后置回读，在剩余时间内继续 |
| 页面和信息无变化，也无合法下一动作 | 有界停止，不等到 45 秒才退出 |

观察优化只处理已测得的关键路径：下一步只需当前相关控件和上下文，操作后复用新鲜回读；确认多次逐元素／逐属性往返是主要耗时时，再局部批量采集。必须保留组归属、禁用态、当前引用及动作时校验；不通过忽略读取错误换取速度，不重开全仓观察器重构。

## 9 验证与独立签收

验证矩阵只以 [Test Skill](skills/test/SKILL.md) 为准，质量口径以 [Eval Skill](skills/eval/SKILL.md) 为准。先复用现有行为覆盖，只为本轮真实遗漏补反例；不以模块或测试数量驱动扩张。

### 受控行为

| 失效机制 | 必须证明的正常行为及反例 | 优先复用入口 |
| --- | --- | --- |
| 必填服务类别无法选择 | 相容类别选择后读到该类别库存并展示；其他类别、无许可／禁用或带实际承诺的动作不误放行 | browser-read-fixture、TableCheck Adapter、native-discovery-composition |
| 类别变化导致错库存 | 切换后请求读回、库存更新可完成；旧类别库存、重置的日期人数时间、迟到旧结果不接纳 | 同上，加 read-assessment／Grounding 与 diagnostic-evaluator |
| 类型标签使事实过早结束 | 详情不足→菜单直接支持→合格交付；菜单仍不足保持 UNKNOWN；已充分时不多读 | native facts、website facts、model-fact-judgment 及原生组合 |
| 官网内容归属错误 | 可确认同店资料被接纳；错分店或品牌菜单无本店适用依据不接纳 | 事实组合、身份及原始引用核验 |
| 慢更新被过早截止 | 来源在 30 秒之后、45 秒以内完成有效更新，能够回读并接纳；无路可走的对照提前停止 | 现有 deadline 覆盖、本地真实 Chromium 异步 Fixture |
| 日期观察与限制混淆 | 漏观察后正常展开可完成；明确限制／错误日期保持拒绝，恢复不新增预算 | Tabelog 控件及 browser-read-fixture |
| 局部限制或重开绕过预算 | 有效配置确实生效；换页不重置累计额度，取消／截止不接纳迟到成功 | Executor、Router 及实际 Runner composition |

反例优先保留修复前的目标断言失败；用真实 DOM 状态或原始来源结果核对操作，不能由 Fixture 直接替模型选中正确项。类别混用和事实追查均须穿过生产 Interpreter、Compiler、Runtime、Router、Adapter、Grounding 和展示链，仅替换模型传输或外部来源。新增场景名可用于 Harness 注册，绝不进入产品分支。

至少一个综合受控成功场景同时包含：正常发现 → 必需类别选择 → 介绍不足及菜单补证 → 有界异步库存更新 → 实际 PRESENT_RESULTS。负对照在所属最低成本层覆盖，不机械复制为多套完整链路。既有 pending-first、当前批短批、首候选失败继续、来源顺序、请求保真和有界无结果回归保留。

### 运行顺序与停止点

1. 完成相关 Adapter／Domain／真实组合测试和本地 Chromium 控件验证；合法历史原文可用时做 Replay。重建页面与合成变体明确标记，不称为真实 Replay。
2. 运行适用离线门禁：typecheck、arch:check、npm test、build，以及本次 DOM 改动的 test:browser:fixture。已通过后只因新增改动、失败或未解决问题重跑相关范围。
3. 保存真实组合 execution artifact，独立评价类别、归属、请求和库存原始证据。Evaluator 增补范围核验；未知事实语义或官网归属无法自动判定的部分保留人工审查，不使用生产 eligible 标志作为 oracle。
4. 同一代码及有效预算上，运行一次包含新能力的已注册固定来源真实模型综合场景。它须让模型实际完成选项及相关入口决策、最终展示；只重跑旧 TABLECHECK_DISCOVERY_RECOVERS 不能证明新增能力。
5. 固定来源通过后，运行一次完整 H001 Live。任一阶段失败就保存证据、定位首个阻断，不自动追加整轮重跑或预算；后续只修直接阻断本轮承诺的问题。

拟定外部运行批次为一次综合固定来源真实模型加一次完整 Live，每次最多 500 秒／50 次全部模型调用；不是自动获准执行，亦不继承历史“三连跑”的次数。正常通过即停止。确需前置来源探针时单独列明额度和目的，不与完整 Live 混报。

六项既有必评维度保持：权威条件、所需证据、调查行为、最终声明、完成结果、资源。关键维度 NOT_EVALUATED 不能作为完整交付通过。Mock、本地 Chromium Fixture、Replay、固定来源真实模型和 Live Read-only 分别汇报；本切片不进行预约、支付、取消或其他 Controlled Live-write。

## 10 运行入口与冻结记录

以下离线命令已存在于 package.json。仅编写本计划不需要运行产品测试；实施时按上一节顺序使用：

```bash
npm run typecheck
npm run arch:check
npm test
npm run build
npm run test:browser:fixture
```

固定来源复用 `npm run eval:restaurant:agent-loop:native-fixed-source-model`。实施中在现有来源工厂、Runner 和独立 expectation 注册综合场景，并保存最终实际命令；当前场景注册与 300 秒参数上限尚未支持本计划的新验收，不能宣称已可直接执行。

完整 Live 的目标命令如下，必须在实施、离线和固定来源门槛通过，且确认适用授权后使用。它选择 canonical H001 的“今晚”，不修改原请求：

```bash
PRAXIS_ALLOW_LIVE_RESTAURANT_READ=1 \
PRAXIS_ALLOW_BROWSER_RUN=1 \
PRAXIS_ALLOW_LIVE_MODEL_EVAL=1 \
PRAXIS_BROWSER_ENGINE=LOCAL_CHROMIUM \
PRAXIS_LOCAL_CHROMIUM_INTERACTIVE=0 \
PRAXIS_EVAL_ALLOW_TABELOG_MANUAL_INTERVENTION=0 \
npm run eval:restaurant:agent-loop:hybrid-live-read -- \
  --case h001 \
  --native-discovery \
  --timeout-ms 500000 \
  --max-model-calls 50 \
  --max-provider-browser-ms 45000 \
  --max-candidate-browser-ms 60000 \
  --max-browser-operations 30
```

执行前检查东京时间下目标窗口仍有效。若本轮要延续“明晚”诊断，必须先明确标记独立 variant，使用现有 `--case-source`、parent dataset/hash 机制，并记录对应日期；不能静默把今晚改成明晚、沿用历史 10 月 4 日或将变体称为原版 H001 通过。

保持既有可用网络，不为本轮添加代理切换／备用 Provider。自动化性能验收不启用人工暂停来延长实际运行时间；如确需人工接管，将其单独记录为不同运行条件。单纯来源连接失败不触发无限网络诊断。

每次外部运行前冻结：代码 commit 与未提交相关源文件 hash、配置、Prompt／Schema／Evaluator 版本、数据集和场景 hash、输入及物化时间／位置、运行模式和次数。允许保留明确归属的未提交工作，不要求清除用户改动；受控验收后改变代码须重跑受影响门槛，不能把新代码配旧测试结果。

执行产物先保存且不可覆盖，随后独立 evaluation，最后 acceptance sidecar；评价失败保留已保存的执行事实。可复用现有 artifact evaluator 补评，不为补评重跑网站。

## 11 诊断与最终报告

在现有 trace、source documents 和 artifact 中补最小字段，不建设新遥测系统。类别原始证据保留组与选项、实际状态、请求、结果关联；事实保留缺口、已访问相关入口、原文引用和停止原因。沿用脱敏规则，不把整页 HTML、Cookie、凭据或无关 PII 加回日志。

| 报告项 | 必须说明 |
| --- | --- |
| 交付 | 实际展示的门店、来源、日期、人数、时段、适用类别和 HARD 依据；未交付则明确写零 |
| 时间 | 整单实际耗时、首个候选具备完整资格时刻、实际展示时刻；后两者不能混为一谈 |
| 耗时分布 | 导航、观察、模型、等待及其他／未归因时间；嵌套计时去重，不能把重叠耗时相加 |
| 调用与预算 | 模型按 purpose 汇总及总数、适用局部操作和来源尝试、实际触发的首个上限 |
| 调查结果 | 支持、冲突、仍未知、来源失败与未到达分别说明；未知不是不提供或无位 |
| 剩余阻断 | 具体缺能力、错误动作、事实不足、真实库存限制或有效进展被截止；给最小下一步 |
| 验收范围 | 离线、真实模型、Live 各自结论，未评维度及人工核验，不以安全退出代替产品完成 |

首个合格时刻优先从已有证据时间和轨迹重建，由独立核验确认；没有足够证据则报告无法确定，不使用更早的单纯库存阳性时间替代。已有足够观测就停止补指标。

500 秒是上限，不是目标耗时。380 秒取得并实际展示合格结果，应报告“500 秒开发预算下通过，尚未达到原 300 秒目标”。只有同一受控环境和其余条件固定时才作严格性能比较；日期和网站状态变化的 Live 只比较实际到达阶段及结果，不据单次运行宣称长期成功率。

## 12 收敛规则与交付清单

增加时间或额度只依据一次运行中可定位的有效进展：如果缺的是合法动作、相关入口、结果绑定或完成条件，先补能力；如果来源结果已经明确，立即结束；如果确实在推进且被某个上限截断，说明剩余动作及其证据，再只调整该项。不得增加同页循环、备用 Provider、多级重试或每页重置额度作为默认处理。

任何新问题只有直接阻断当前交付或涉及错误成功、授权、隐私等安全不变量才并入。出现范围扩张、口径漂移或用局部测试替代整链时，按 [Planning](skills/planning/SKILL.md)主动报告“原承诺、当前偏离、影响、收敛方案”；不为已授权的正常实施新增审批。

- [ ] 窄 ADR 明确官网事实路径和本次开发预算，历史决策保留。
- [ ] 预算按实际入口生效，Runner／Web 同等能力声明有真实 composition 依据。
- [ ] 单选观察、来源许可、实际选中、完整请求、类别库存及最终资格贯通。
- [ ] 缺失 HARD 能沿相关来源追查；充分证据及时停、无依据保持未知。
- [ ] 日期真实缺口及慢更新有正常与反向对照，未添加无依据兜底。
- [ ] 适用离线矩阵、独立证据核验及固定来源真实模型各有对应代码证据。
- [ ] 完整 H001 Live 的实际展示与未完成项如实记录，不把单店探针升级为整单通过。
- [ ] 实施后按范围同步 Capability Matrix、Domain／Architecture／Contracts、STATUS、DEVLOG、TEST-LOG；退役被替代路径和重复测试。
- [ ] Pilot 前不新增兼容分支；若发现真实生产数据或外部消费者，先明确迁移／保留方案。
- [ ] commit、tag 和 push 分别报告；远端推送仍须用户明确授权。

旧原生发现及后段 Playbook 保留为前期范围和历史背景；本计划新增能力的当前事实只在 STATUS 更新。文件存在或清单勾选均不替代对应执行与验收产物。
