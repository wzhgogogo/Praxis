## 1. 问题与切片

用户要求同时验证复杂网站上的操作、信息理解、跨页记忆和条件变化，允许替代日期/时段、筛选勾选与撤销、搜索、滑条、滚动和地图交互。

这轮使用隔离 Stagehand 4.1.0 的 snapshot/observe、现有 DeepSeek Gateway，以及 Playwright 执行。不是产品 BrowserTaskExecutor、Restaurant Runtime 或 Policy 的端到端接线。生产源码和主依赖未修改；已有其他工作改动保留。脚本、固定页面、模型自主选路分别记录，避免将脚本补救计为自主成功。

开始前的计划在本机 `.eval-artifacts/browser-capability-suite-2026-09-16/PLAN.md`：最多 24 次累计模型调用、每商户最多 6 次候选观察、每 browser run 12 分钟。三个已知商户入口由研究者提供，未测自主发现。偏好 9/19 19:00 两人，允许 9/20 和 17:00–20:00 替代方案。记忆修订请求为 9/20 20:00 四人。

同一诊断 cohort 内有探针修正与零模型对照，逐批保留代码副本和失败结果；不是冻结基线、随机 A/B，也不用于宣称框架成功率。无私有 Holdout、个人浏览器 profile、条款确认、身份填写或预约提交。外部副作用没有独立网络审计，不能报告实测副作用计数为零。

## 2. 验收设计

| 维度 | 证据与判定 |
|---|---|
| 操作 | 目标状态前后比较；不以 API 返回或截图变化单独判成功 |
| 观察 | 对比 Stagehand 快照与页面正文/DOM 状态；缺失状态与实际未选择分开 |
| 理解 | 金额、套餐、座位、人数、时间及规则关联；不只检索关键词 |
| 记忆 | 两店抽取笔记后，用新模型请求只看笔记比较；不再提供原页面 |
| 请求修订 | 改人数、日期和时间后，不将旧库存支持新请求；保留适用规则 |
| 证据更新 | 新套餐页补充取消规则，替代时段仍标替代，不伪造预约确认 |
| 独立核验 | 原 execution 与 evaluation 分开；引用匹配只证明文本存在，语义支持性另审 |

## 3. 实际结果

### 3.1 操作：脚本可执行能力

- **真实浏览器本地 Fixture**：勾选/取消、滑条键盘调整、搜索结果、正确滚动容器通过；敏感提交和禁用目标拒绝，人数及替代时间允许。合成 Fixture 不是 Replay。首次沙箱本机 listener EPERM 无模型调用，授权环境重跑通过。
- **TableCheck 搜索**：输入 Ginza 并搜索，URL 与结果内容对应。不是模型自主搜索。
- **完整 Filters 弹窗**：TC Points 勾选、撤销并恢复；内部容器 scrollTop 从 0 到 600；Sushi 勾选 Update 后重新打开仍勾选；Reset 后取消勾选，均有独立 DOM 断言。
- **预算滑条**：键盘使内部档位 15→14，拖动使 14→10，页面显示 ¥30,000，应用后摘要为 ¥0–¥30,000。内部值是档位，不是金额，不能直接拿 aria-valuenow 当价格。没有测试完所有档位或任意价格的精确定位。
- **地图**：滚轮缩放和平移后截图发生变化；能识别 Zoom in/out、Map canvas、带商户标识的 DOM marker。marker 点击超时，地理边界未独立验证；地图完整交互未通过。第二次地图步骤中异常发生在记录最终状态之前，因此不能补造缩放/平移的中间证据。
- **替代日期、人数、时段**：零模型对照最终进入八芳套餐页，正文确认 `September 20, 2026 (Sun) 7:15 PM (JST)`、`Number of guests4`，并展开两个 Plan details。日期/人数/时间由正文确认，不只看 URL。它是替代查询路径通过，不是模型自主完成或已预约。

保留的失败包括：开始打开独立 Budget 弹窗，却按完整 Filters 寻找复选框；错误区域滚动未改变目标容器；Reset 关闭弹窗后继续寻找 Update；替代对照最初只检查 17:00/20:00，漏掉可见的 19:15/19:30。这些属于探针缺陷，不能归咎网站或框架。

### 3.2 模型流程：尚未完整通过

- **141**：2 次模型 observe，经 Playwright 执行进入匹配 9/19、19:00、两人的公开表单 URL，并读到套餐/规则。不把 URL 或表单入口视作独立库存确认。
- **八芳、Sendou 初次**：各 1 次模型 observe 选择背景日历，语言遮罩导致 Playwright 点击超时。初次错误记录过短，复验加入具体点击失败反馈及先处理遮罩的指令。
- **复验八芳**：关闭语言提示、点击日期后反复提议同一日期；最终返回五个候选，包含允许的其他日期和 17:00/20:00 时段。探针要求单一动作而停止。
- **复验 Sendou**：反复提议相同日期，到 6 步预算仍未进入套餐页。

共 15 次动作观察调用。重复提议被探针阻止，未盲目重复点击。

**关键归因修正：`observe` 是动作候选接口，不等于完整任务规划器。** 用它承担所有进度管理、替代选择与恢复，再强制只能返回一个候选，会把 harness 的协议限制混入框架质量。此次可证明候选发现和状态利用不足以自动闭环；不能由此认定 Stagehand agent 模式同样失败，因为没有测试该模式。

### 3.3 信息抽取与显式笔记记忆

输入为本轮真实页面采集：141 表单快照 28,707 字符；八芳商户页快照 49,909 字符，均未截断。两次模型抽取，之后比较/请求修订各一次，输入只有笔记，不包含原页面。

- 141 抽取 11 条、八芳 10 条；20 条引用能在序列化快照与正文中同时按空白归一化匹配。1 条八芳消费区间引用未通过双重匹配，被排除。**20/21 是引用文本包含检查，不是事实准确率。** 要求“最多 10 条”的提示未被严格遵守，数量约束需由契约执行。
- 只凭笔记，模型仍能区分 141 的 ¥5,900/¥8,900 套餐与包间最低消费 ¥60,000；八芳 ¥13,000/¥18,000 套餐与仅午餐可用的 180 分钟方案。
- 改为 9/20 20:00 四人后，模型指出 20:00 超过 141 已读方案的 19:30 结束时段，要求重查库存，没有把旧时段直接确认为新请求可用。
- 比较、修订各 20 条结构化 claim 的 `(merchant, factId)` 引用均存在；自由文本只写 F1/F8 等局部 ID，跨店存在歧义，正式输出必须使用明确来源标识。

**独立审阅发现的错误与不足：**

1. 把“9 人以上必须电话预约”扩写为“四人仍可以在线预约”，属于不受引用支持的逆向推断。
2. 把快照未编码选中状态写成“没有选择日期/人数”，而独立 DOM 有 active 人数/时间状态。观察缺失不能变成否定事实。
3. 141 部分价格引用仅包含金额，缺少套餐名称和税费上下文。完整原文可支持对应关系，单条保留引用却不能独立支持整句话。
4. “四人可能需要不同甜点安排”是源文未确证的推测。
5. `unknowns` 也是模型输出，本轮没有逐条绑定证据；不能让未验证的未知项说明变成事实入口。

因此证明的是：**显式来源笔记可以让独立模型请求继续利用已读信息，但记忆会保留并传播错误推断。** 未证明长期记忆、任意页面无遗漏、视觉理解或产品持久化。

## 4. 优化方案

### 第一优先：接通一个能完成任务的最小闭环

保留 Playwright 执行，以此次两站作为真实使用者验证下列职责；不要并行部署多套长期 Agent loop：

1. **观察**：输出活动弹窗/区域、元素映射、选中与禁用状态、必要文本分段。Stagehand snapshot/observe 作为候选能力，需衡量信息覆盖和成本，尚未决定生产引入。
2. **下一步选择**：项目现有 Browser Agent 接收目标、合法动作、已发生变化和具体失败反馈；`observe` 返回的多个候选供其选择，不把候选接口当规划器。替代日期/时间来自本次任务许可，不能暗改原目标。
3. **执行与核验**：Playwright 受控执行后，核验新标签页、过滤条件、正文摘要、数值和选中状态。重复日期而无新变化时，返回明确“已选中”，并让 Agent 选择有价值的其他合法动作。
4. **事实笔记**：复用现有来源 Evidence/Context 机制，最小记录来源、原文片段、适用商户/套餐/日期/人数和观察时间。模型摘要是非权威笔记；不要新增通用长记忆平台。
5. **证据接纳**：引用存在检查与语义支持检查分开；尤其阻止否定反推、跨套餐金额混用、缺状态推断未选择。请求修订后重新绑定动态结果，保留历史而不让其支持当前库存。

下一实施切片应从现有 BrowserTaskExecutor/观察契约接线开始，使用同一真实 composition 验证“选择候选 → 执行 → 状态变化 → 带证据答案”，然后再做同口径 Live。先复用现有控件/Executor 测试加入此次独立失败机制，不把隔离 runner 复制成第二套生产执行器。

### 第二优先：补足按需视觉观察

地图标记、图标库存表、无语义滑条等仍可能需要截图与视觉定位。当前 DeepSeek 测试是文本输入，没有视觉模型对照；不能声称已证明视觉方案或 Midscene。先定位实际缺失信息，再决定视觉模型和接入方式，遵守既有模型 ADR。

### 选型结论

当前支持“Playwright 执行 + 更完整的观察 + 项目自己的规划与证据记忆”的验证方向。Stagehand 可能减少观察/定位代码，但未证明其收益大于部署和维护成本；尚不支持整套替换，也不支持因本轮失败弃用。browser-use、Midscene 没有在这轮同口径实测，不能给出优劣排名。

### 最终证据更新与用量

`1789533860685-refresh-memory` 用 1 次模型调用，将旧八芳笔记与新套餐页正文一起提供。模型正确输出 `ALTERNATIVE`、`exactRequestSupported=false`、`bookingConfirmed=false`，补充 9/18 05:59 JST 的免取消费截止时间，同时仍将押金/no-show 条款列为未知。

仍有一个明确错误：从正文列出的 `0 children / 1 child / 2 children / 3 children` 选项推断当前选中 0 children。输入没有选中值，不能据此确定状态。这与此前日期/人数的观察缺口一致。8 条引用中 7 条匹配正文；另一条是正确来源 URL 元数据，不能用正文匹配器误判为编造，应区分来源类型。

最终共 **20 次 DeepSeek 调用 / 228,988 tokens**，其中 15 次候选观察、5 次信息/记忆诊断；未计算货币成本。无更多模型复跑。所有完成批次浏览器均记录 CLOSED；清理、链接和 diff 另核验。整体结果为部分能力成立，模型完整流程和可靠语义记忆未通过，不报告总通过率。
