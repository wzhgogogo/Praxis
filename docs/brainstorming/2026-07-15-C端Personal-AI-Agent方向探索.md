# Project Praxis（知行）：C端 Personal AI Agent 方向探索

> **Not just answers. Outcomes.**

**中文名：知行｜英文名：Praxis**

Praxis（知行）是一个面向个人生活事务的 Personal AI Agent：通过 Public Knowledge 理解现实世界中的事务与流程，通过 Private Knowledge 理解具体用户，并在获得授权后进行规划、执行和持续跟进，直到产生真实、可验证的结果。

本文起源于 2026-07-15 的方向讨论，项目名称与定位于 2026-08-03 更新；2026-08-04 进一步确定从日本市场 Local 场景开始 Build。原始讨论判断继续保留，供后续验证和迭代。

## 当前 Build 决策（2026-08-04）

Praxis（知行）从 **日本市场的 Local 场景**开始 Build，以聚会、餐厅、预约、交通和外出安排作为第一批代表性任务。

当前目标不是依据 Local 查询占比直接证明产品成立，而是通过真实产品验证：用户是否需要一个能够保存任务状态、理解个人约束、整合本地信息、跨平台推进并持续跟进到结果的 Personal AI Agent。

第一阶段优先使用 API、Deep Link、邮件/日历和用户最终确认，不以万能 Browser Agent 或100%自动执行作为启动前提。完整决策见：`2026-08-04-日本Local市场切入与Build决策.md`。

## 起源

从 WorkBuddy 上和 hy3 讨论的一个想法出发：能不能做一个面向个人生活的 AI agent？

核心场景举例：
- 家庭消耗品管理（醋用完了要比价买、不同物品消耗周期不同）
- 定期事务（看医生、体检、车保养，全靠人脑记然后自己去约）
- 这些琐事全靠人脑记忆，容易遗漏

## 核心问题：C端 agent 有没有空间？

当前行业现状：所有 agent 都在卷 ToB/办公，C端几乎空白。

### 为什么所有人都在做 ToB

```
办公场景：
  ✅ 操作对象是数字化的（文件、代码）→ AI 天然能操作
  ✅ 价值可量化（省时间 = 省钱）→ 容易卖
  ✅ 容错高（改错了可以 revert）

个人生活场景：
  ❌ 操作对象在物理世界（醋、医院、车）→ AI 够不着
  ❌ 价值难量化 → 难卖
  ❌ 容错低（约错医生不行）
```

**本质：数字世界 AI 能直接干活，物理世界 AI 只能提醒你去干活。**

### 但 C 端不是没空间

关键是找到"AI 能完成闭环"的场景，而不只是提醒：

1. **纯数字交付**：个人财务报告、内容创作、学习计划
2. **有成熟 API 的生活场景**：外卖、打车、快递、缴费、订机票
3. **信息整合 + 决策辅助**：跨平台比价、选学校、选房子

## 产品定位：Project Praxis（知行）——从“富人的管家”到“人人的管家”

今天有钱人的生活：

## 两个核心难点

### 难点一：怎么获得数据

**结论：邮件是最好的单一数据源。**

海外几乎所有交易行为都有邮件痕迹：

```
购物：Amazon/Walmart/Target/Instacart → 订单确认、发货、送达
订阅：Netflix/Spotify/各种 SaaS → 月度扣费通知
财务：银行月度账单、信用卡交易提醒、Venmo/PayPal 转账
预约：医生/牙医/理发/车保养 → 预约确认和提醒
旅行：航班/酒店/租车 → 确认和提醒
住房：水电煤账单、房租/物业缴费
其他：学校通知、政府税单、保修凭证
```

**光邮件一个数据源就能还原 80-90% 的个人生活画像。**

邮件覆盖不到的部分 + 补充方案：
- 线下现金消费 → 银行/信用卡流水（Plaid）
- 健康数据 → Apple HealthKit / Google Fit API
- 偏好学习 → 用户行为观察
- 家庭协作 → 简单语音/文字输入

### 难点二：怎么打通外部平台

**结论：海外比中国容易太多。**

```
中国：微信/支付宝/美团封闭生态，API 不开放 → 基本没法做
海外：几乎所有主流平台都有开放 API + MCP/connector 生态爆发
```

已经能打通的平台：

| 场景 | 平台 | 接口 |
|------|------|------|
| 购物 | Amazon, Walmart, Target | Product API, 联盟链接 |
| 外卖/买菜 | Instacart, DoorDash | API |
| 预约医生 | Zocdoc, MyChart | API + FHIR 标准 |
| 财务 | 所有银行 | Plaid API |
| 日程 | Google Calendar, Outlook | 成熟 API |
| 邮件 | Gmail, Outlook | 成熟 API |
| 智能家居 | HomeAssistant, SmartThings | 开放 API |
| 打车 | Uber, Lyft | API |
| 旅行 | Booking, Expedia, Amadeus | API |

关键趋势：平台在主动接入 AI agent（Codex 等），心智从"保护流量入口"转向"成为 agent 执行后端"。

## 隐私和存储：怎么做到数据不上云

### 关键问题：手机存储不会爆吗？

不会。因为**不需要存原始数据**。

```
原始邮件（50KB，留在 Gmail 不下载）：
  "Your Amazon order #123-456 has shipped. 
   Item: Kikkoman Soy Sauce 1L, $8.99..."

只存结构化摘要（0.5KB）：
  { type: "purchase", item: "Kikkoman Soy Sauce 1L", 
    price: 8.99, platform: "Amazon", date: "2026-07-15",
    category: "condiment", estimatedConsumption: "60 days" }

压缩 100 倍。一年结构化数据约 50MB，手机轻松存下。
```

### 最务实的架构

```
┌──────────────────────────────────────────┐
│              用户手机                      │
│                                          │
│  Gmail/Bank API → 解析引擎（端侧）        │
│                   正则+规则（80%场景）     │
│                   端侧小模型（20%兜底）    │
│                       ↓                  │
│              结构化知识图谱（~50MB/年）     │
│                       ↓                  │
│              推理 & 建议（端侧规则引擎）    │
│              "纸巾快没了" "该看牙医了"     │
└───────────────────────┬──────────────────┘
                        ↓ 需要联网时
              调外部平台 API（比价/下单/预约）
```

核心原则：
- **读**数据 → API 从 Gmail/银行拉（数据留在原处）
- **解析**数据 → 端侧处理（正则为主，小模型兜底）
- **存**数据 → 只存结构化摘要
- **推理**决策 → 端侧规则引擎 + 小模型
- **执行**操作 → 这一步才联网，调平台 API
- **你的服务器上什么都没有**

## 各地区合规可行性分析

### 总结

**结论：能做。没有任何地区是"不可能"的。**

优先级排序：

```
1️⃣ 新加坡 — SGFinDex（政府级财务数据聚合），合规最友好，做 MVP
2️⃣ 美国 — 最大市场，Plaid 生态成熟，合规门槛最低，竞争激烈
3️⃣ 日本 — APPI 宽松，用户付费习惯好，亚洲扩张跳板
4️⃣ 韩国 — MyData 框架利好，PIPA 较严格
5️⃣ 欧盟 — 市场大但合规成本高，PSD2 开放银行是利好，后期进入
6️⃣ 东南亚其他 — 基础设施不成熟，等一等
```

### 各地区详情

**🇺🇸 美国** — 可行性：高
- 无联邦统一隐私法，主要靠 consent
- Plaid 生态成熟
- Gmail API 路径清晰（需 Google OAuth 审核 + CASA 安全评估）

**🇪🇺 欧盟** — 可行性：中
- GDPR + EU AI Act（2026年8月高风险条款全面生效）
- 个人助手一般是"limited risk"，不算高风险
- PSD2 开放银行 = 银行被法律要求开放接口（利好）
- 合规成本高但可通过 Plaid 等中间商降低

**🇯🇵 日本** — 可行性：高
- APPI 比 GDPR 宽松，consent 可 opt-out
- 银行 API 法修正案推进中
- 用户付费习惯好

**🇰🇷 韩国** — 可行性：中高
- PIPA 较严格，2023年修订新增自动化决策权利
- MyData 框架让银行数据获取合法化

**🇸🇬 新加坡** — 可行性：最高
- SGFinDex = 政府主导的个人财务数据聚合平台（极利好）
- AI Governance Framework 有指引但非强制
- 数据跨境允许

**关键发现：** 如果做端侧处理（数据不上传你的服务器），大部分合规问题直接消失。你不是"数据控制者"，你只是提供了一个处理工具。

## MVP 数据与执行策略（2026-08-04更新）

```
Phase 1（日本 Local 核心闭环）：
  用户提出聚会或外出目标
  → 补齐时间、人数、区域、预算和偏好
  → 搜索、比较候选地点并保存任务状态
  → 通过 API / Deep Link / 用户确认推进
  → 写入日历、提供交通和关键时间提醒
  → 跟进到安排得到确认

Phase 2（日本 Local 深化）：
  → 预约确认邮件解析、多参与者协调、变更和异常处理
  → 扩展城市、平台和 Local 类别

Phase 3（扩展场景和市场）：
  → 根据实际使用、任务完成率和留存决定下一步
  → 复用任务状态、执行路由和 Public Knowledge 生产体系
```

## 最大的威胁

**Apple Intelligence + Siri**
- 有系统级权限（通讯录、日历、健康、支付）
- 有硬件入口（iPhone、Watch、HomePod）
- 55%+ 海外用户是 iPhone
- 但：做得慢、不做跨平台、不做深度金融合规

**窗口期预估：1-2 年**

应对策略：
- 做 Apple 结构性不做的事（跨平台、深度财务、地域特色服务）
- 或做到被收购

## 和 ToB 方向的对比

| | C端个人管家 | ToB 企业 AI 中间层 |
|---|---|---|
| 需求 | 真实但付费意愿不确定 | 真实且强 |
| 市场 | 极大（所有人） | 大但获客慢 |
| 护城河 | 用户数据飞轮 + 习惯 | 集成+权限+数据 |
| 巨头威胁 | Apple/Google | ServiceNow |
| 变现 | 订阅 $5-15/月 或 CPS 佣金 | $5000+/月/团队 |
| 时间窗口 | 1-2年 | 更长 |

两个方向不冲突，底层能力（connector 集成、数据解析、权限管理）是共通的。
