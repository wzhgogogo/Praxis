# Praxis Test

- Document revision: 1.0
- Last updated: 2026-09-24

Test负责跨阶段行为覆盖、验证方法、检错有效性和故障关闭。质量维度、评分单位和验收门槛属于[Eval](../eval/SKILL.md)；当前产品合同、已运行证据和未覆盖项分别以链接的权威文档、[STATUS](../../STATUS.md)和[TEST-LOG](../../history/TEST-LOG.md)为准。

## 验证矩阵

| 改动 | 必要验证 |
|---|---|
| 纯文档/配置说明 | 链接、命令/变量引用、权威一致性、diff；不运行付费或Live测试 |
| 局部实现/重构 | typecheck、arch:check、相关行为测试、build；共享路径受影响时运行npm test |
| Runtime、Policy、授权、State/Schema、Verifier、P0路径 | typecheck、arch:check、npm test、build及对应状态/副作用不变量 |
| Provider/Browser Adapter | Contract；操作DOM时加真实浏览器本地Fixture；有合法样本时Replay；改变平台能力声明时单独Live Read-only |
| Search/排序 | Unit与Search Harness；真实响应兼容性变化时Replay或明确缺口 |
| Web交互 | 客户端检查、相关HTTP/API与关键浏览器交互；响应式标记不能替代视觉/设备验证 |
| 语义Prompt/Contract/Scorer | 对应Unit、固定开发Regression及Eval协议要求；不自动运行或读取私有Holdout |
| Holdout纯标注数据 | 仅在任务允许修改数据时按Holdout协议做Preflight；完成后才做严格Preflight |
| PostgreSQL持久化 | PGlite集成；另经测试数据库写入授权运行真实PostgreSQL smoke |
| 冻结Goal/Scheduler探针 | 仅影响该路径时运行`npm run test:probes`；不属于当前Restaurant默认产品门禁 |

四条离线代码门禁是`npm run typecheck`、`npm run arch:check`、`npm test`、`npm run build`。通过后只在新改动、失败或未解决风险需要时重复，不按测试数量扩张范围。

## 覆盖推导与检错有效性

先从当前权威合同写出“用户承诺 → 权威输入/状态 → 允许或禁止的动作 → 证据生产与接纳 → 完成、停止或恢复”，再找能违背它的实际机制。每项覆盖写明适用理由；合同或失效机制不成立时写`不适用`，不机械做笛卡尔组合，也不以H001等Case ID生成产品分支。

实现和既有测试可以证明当前行为或暴露缺口，不能自行定义产品语义、Gold或验收门槛。权威文档与实现证据冲突、或只有实现而缺少应然合同的时候，记录差异、按已接受安全边界fail closed，并要求在实际切片由权威文档或ADR决定；不要用测试样本把实现细节升级为产品规则。

| 覆盖向量 | 要问的失效问题 | 何时适用 |
|---|---|---|
| 正常控制 | 独立输入和来源事实能否走到承诺结果？ | 每个重要承诺至少一个 |
| 误接纳 | 冲突、错误身份、过期/错误请求、无授权或不可证实结果会不会被放行？ | 资格、证据、状态或副作用会决定成功时 |
| 误拒绝 | 合法输入、合格证据或合法后续动作会不会被错误阻断？ | 有选择、批量、刷新或恢复路径时 |
| 未知与冲突 | 缺证、来源失败、冲突观察或未到达会不会被伪装成成功、失败或穷尽？ | 外部观察、诊断或评价有三值/未到达语义时 |
| 变化与恢复 | 请求、时间、取消、重启、迟到响应或刷新失败会不会覆写权威较新状态或复活旧成功？ | 合同含时效、版本、异步、取消或恢复时 |
| 资源、批次与隔离 | 预算是否累计且Task隔离；跨批、候选、来源和顺序变化会不会错配、提前结束或绕开限制？ | 有预算、批处理、多个候选/来源或并发时 |

覆盖选择还要检验测试自身没有替被测代码预先完成关键判断：来源样本、身份资料、用户条件、时钟、预期和评分结论应可独立变化。一个根因可限制本轮修复范围，但不免除相关边界；同一输入、路径和失败后果只保留一处主覆盖。

每项重要行为保留正常对照，并以修复前失败、受控错误或隔离副本证明目标断言会失败。启动、类型、环境或无关运行错误不算检错。有限变异只服务当前风险，不引入全仓变异工程或污染样本、artifact和工作区。

安全边界从[Arch Guard](../arch-guard/SKILL.md)、[Policy/Execution/Verification](../../architecture/POLICY-EXECUTION-VERIFICATION.md)和当前Domain合同转化为适用覆盖输入：未授权Commit、重复提交、错候选或错Attempt的成功、跨用户Case/Profile访问、Takeover越权和`OUTCOME_UNKNOWN`后的盲重提/换店必须被拒绝。每个适用外写切片还检查新Proposal是否取得新Authorization、Verifier是否独立解释Outcome；这些是安全不变量，不由普通成功率替代。

## 执行链变更的三步验证

适用于改变用户目标、必要字段、调查动作、证据契约、完成/停止条件或Web后续操作；纯文档和无关局部修改仍按矩阵。验收围绕用户行为。

1. **跨模块集成回归。** 从Runner或Web的实际初始化入口使用生产组合；只替换模型传输、网络或浏览器来源。保留Interpreter、Compiler、Reducer、Grounding、Validator、Router和持久化路径，不能手填合格Evidence或中间State来宣称链路通过。
2. **结果与诊断核验。** 对执行产出的artifact或其脱敏副本按[Eval的独立核验](../eval/SKILL.md#执行结果与诊断的独立核验)检查支持性、归因和未评估项。评分器通过不替代产品集成通过。
3. **从本地验证到有界Live。** 先完成适用离线矩阵、真实浏览器本地Fixture和Replay/历史artifact补评，再在已授权预算内验证真正的外部不确定性。首次只读契约探针遵循[Planning](../planning/SKILL.md)，不是最终验收。

Smoke只证明启动/连接；脚本化Agent只证明选定路径可执行；模型替身只证明内部契约。没有实时库存可以是正确业务结果，但缺少证据生产能力或无路可走仍是能力缺口。Web与Harness声称等价的能力必须由真实composition接线覆盖，或明确缺口。

### 真实组合集成规则

关键集成测试写明起点/终点、替换边界、独立预期、可捕获故障和不证明范围。实际流程先产出artifact，再由现有Evaluator诊断；手工构造State、Evidence或evaluation只证明局部函数。共享契约改动在同一切片列出Runner、Web和其他实际调用方，修改并退役替代路径。

调查顺序可以不同；互相独立的合法读取验证共同结果契约，不穷举排列或比较随机ID。有时序意义的刷新、冲突、取消、跨批或并发另测。预算按run累计且跨run隔离；来源/候选局部失败不能掩盖仍合法的动作，真预算停止、取消和内部失败也不能改写为正常无结果。

### 行为覆盖与测试有效性

交付对每个声明的主要失败机制附下表。无法核验的项保持未完成或阻断，不用全仓全绿替代。

| 主要失败类型 | 能抓住的测试入口 | 检错证据 | 未覆盖边界 |
| --- | --- | --- | --- |
| 例：异店库存被错误关联 | 真实composition集成测试 | 故意串店时目标断言失败，正常对照通过 | 当前网站身份资料 |

已知故障先保存未修代码下、目标契约断言失败的反例；修复后复跑该反例、实际链路产物和独立诊断。先按首个失败层做最小定位，再在共享影响确实存在时做跨场景回归；不要反复用Live定位已知确定性接线故障。

## 故障关闭

一个故障只有在以下适用项均有证据时才关闭：原反例在未修路径上失败且目标断言有效；修复后反例和相关边界通过；真实调用链产出artifact；独立evaluation没有把旧缺陷换成错误成功或未解释的失败；验证矩阵要求的门禁已运行，外部不确定性明确列为已验证、未运行或不适用。外部缺口不能因离线修复而消失，已知未覆盖范围仍留在交付中；本地机制关闭不等于未验证外部行为或整体用户验收关闭。

若本轮修复的是验证体系本身，可以交付仍失败的业务回归，但该回归必须进入默认`npm test`；不得用`skip`、`todo`、反转断言或排除文件掩盖。关闭的是验证缺陷还是产品缺陷必须分别报告。

## 每种测试证明什么

| 模式 | 证明范围 | 不证明 |
|---|---|---|
| Unit / Adapter Mock | 参数、解析、状态/错误分支、授权与幂等 | 真实页面DOM与网络行为 |
| 真实浏览器 + 本地Fixture | 实际控件操作、异步状态、等待和恢复 | 当前网站可访问或可预约 |
| Replay | 脱敏真实响应的回归 | 当前站点状态与库存 |
| 真实模型 + 固定来源响应 | 本次模型对工具/Context/失败反馈的理解与受控调查质量 | 当前真实网站可访问、实时库存、长期模型成功率 |
| Live Read-only | 此次环境下连接、门店、请求条件与空位 | 真实提交成功或长期可靠性 |
| Controlled Live-write | 授权范围内真实写入及验证/清理 | 未测平台或任意网站自动化 |
| Embedded-postgres integration | PGlite的SQL/事务/恢复 | 真实PostgreSQL部署 |

首次接入没有Replay时记录缺口，先做受控只读观察；合成HTML不叫Replay。真实模型、Live和数据库写入需要既有授权与预算，环境开关本身不是授权。Mock、Replay、Live Read-only和Controlled Live-write分开报告。

## 测试维护与退役

新增测试前搜索既有同一行为覆盖，优先扩展所属测试，并说明它能捕获哪个现有覆盖遗漏的失败。等价数据变体使用具名参数化断言；不同故障机制不为减少数量塞进一个大测试。替换实现时同步更新有效断言、删除旧路径和重复回归；保留真实状态所需迁移验证。

不绑定无契约意义的私有调用次数、文案、CSS断点或源码形状。时间/重试预算、Secret隔离、授权和副作用次数属于真实契约。脆弱测试修复等待和观察条件，不以重试或放宽断言掩盖失败。默认套件只收当前产品所需的离线测试，浏览器、冻结探针和Live沿现有独立入口运行。

## 运行边界与报告

普通测试不加载`.env`、不调用付费模型或生产服务、不创建真实预约。`test:browser:fixture`只使用本机浏览器与本地Fixture，不读取个人profile；真实PostgreSQL只使用授权专用测试库及`PRAXIS_ALLOW_TEST_DATABASE_WRITE=1`。Controlled Live-write不得在CI运行，并记录验证与清理结果。

报告通过、失败、未运行、不适用及原因，并区分执行模式、实际副作用与未覆盖边界。具体命令以`package.json`为准。
