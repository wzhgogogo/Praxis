# Praxis Test

本文件唯一维护验证矩阵；当前通过数量见[STATUS](../../STATUS.md)，运行命令、失败和证据见[TEST-LOG](../../history/TEST-LOG.md)。模型质量另见[Eval](../eval/SKILL.md)。

## 验证矩阵

| 改动 | 必要验证 |
|---|---|
| 纯文档/配置说明 | 链接、命令/变量引用、权威一致性、diff；不运行付费或Live测试 |
| 局部实现/重构 | typecheck、arch:check、相关行为测试、build；共享路径受影响时运行npm test |
| Runtime、Policy、授权、State/Schema、Verifier、P0路径 | typecheck、arch:check、npm test、build及对应状态/副作用不变量 |
| Provider/Browser Adapter | Contract；操作DOM时加真实浏览器本地Fixture；有合法样本时Replay；改变平台能力声明时单独Live Read-only |
| Search/排序 | Unit与Search Harness；真实响应兼容性变化时Replay或明确缺口 |
| Web交互 | 客户端检查、相关HTTP/API与关键浏览器交互；响应式标记不能替代视觉/设备验证 |
| 语义Prompt/Contract/Scorer | 对应Unit、固定开发Regression及Eval协议要求；不自动运行或读取私有Holdout |
| Holdout纯标注数据 | 仅在任务允许修改数据时按Holdout协议做Preflight；完成后才做严格Preflight |
| PostgreSQL持久化 | PGlite集成；另经测试数据库写入授权运行真实PostgreSQL smoke |
| 冻结Goal/Scheduler探针 | 仅影响该路径时运行npm run test:probes；不属于当前Restaurant默认产品门禁 |

四条离线代码门禁是`npm run typecheck`、`npm run arch:check`、`npm test`、`npm run build`。通过后仅在新改动、失败或未解决风险需要时重复，不按测试数量扩张范围。

## 执行链变更的三步验证

适用于改变用户目标、必要字段、调查动作、证据契约、完成/停止条件或Web后续操作的切片；纯文档和无关局部修改仍按上表。验收围绕用户行为，不按Golden Case ID生成产品分支。

1. **跨模块集成回归。** 先核对当前承诺的必要输入、可执行动作、证据生产者、接纳者、完成/停止条件与用户后续操作是否相接。复用真实Application/Router/Domain/Reducer和生产组合，替换外部模型传输、API响应或浏览器来源；不得把正要验证的Grounding、状态转换或来源证据生产路径mock掉，也不得只手工塞入合格Evidence便声称调查链通过。优先扩展已有测试，以已知失败复现证明断言有效。
2. **结果与诊断核验。** 按[Eval的独立核验](../eval/SKILL.md#执行结果与诊断的独立核验)评估测试产生的artifact或已有脱敏记录的副本，核对结果支持性和失败归因；评分器测试通过不替代产品集成通过。
3. **从本地验证到有界Live。** 先完成本切片适用的离线矩阵、真实浏览器本地Fixture和可用Replay/历史artifact补评，再在已授权余额内运行真实模型或来源。预先说明Live要验证的外部不确定性，不能反复用Live发现已知的确定性接线缺口。首次接入为获得来源契约所必需的有界只读观察可按Planning单独进行，不冒充最终验收。

按本次受影响行为选择覆盖，不机械展开全部组合：目标与必要字段；满足/冲突/未知证据；前批无合格结果后的候选继续；额度耗尽但已有结果可展示或另有有效动作；刷新后的新旧证据取舍；修改需求；并发任务隔离与取消。Web提供的操作应覆盖到最终状态，不能只验证按钮或事件发出。Web与Harness声称等价的能力应有使用真实composition的接线覆盖，允许测试替换外部边界。

Smoke只证明启动/连接；脚本化Agent只证明选定动作路径可执行，不证明真实模型会选择正确动作。没有合格实时库存可以是正确业务结果，缺少证据生产能力或无路可走必须仍作为能力缺口报告。已知故障修复后，在实际流程产物上检查结果和诊断，不能只核对调用次数或增加测试数量。

### 故障定位与复验范围

按首个失败层选择最小诊断：语义故障先验证Interpreter/Compiler，控件故障先验证对应浏览器操作，接纳或状态故障先验证实际内部组合。已知故障以修复前失败、修复后通过的行为反例为依据，优先扩展既有测试；随后核对实际链路产物及独立诊断，最后用有界Live验证尚未消除的外部不确定性。首次未知来源的契约探针适用上文例外，不要求先猜出完整实现。

Live先复验受影响案例；相关阻断关闭后，再按共享影响做跨场景回归。代码修改仍须完成上表适用的离线门禁，不能借局部复验跳过必需检查，也不要求每个小修都重跑H001–H005。每次正式Live记录代码快照（dirty时保留可复现差异或内容hash）、输入/时间/位置、预算和评价版本；运行中不更改该快照，修复后另开记录，原始执行与评价保留。

### 真实组合集成规则

关键集成测试从Runner或Web的实际初始化入口开始；若顶层CLI妨碍测试，提取最小共享组合函数并让CLI与测试共同调用，不能另建测试专用执行器。只替换模型传输、网络或浏览器来源，保留Interpreter、Compiler、Reducer、Grounding、Validator、Router和持久化状态路径。中间State构造仍可作为局部规则测试，但不得称为完整链路验收。

每个关键测试用简短注释标明起点/终点、替换边界、独立预期、可捕获故障及不证明范围，并覆盖以下通用契约：

1. 用户条件、时区/参考时间、位置来源、请求版本、预算和取消信号应在实际需要的层完整传递；已提供不得因漏接线反复补问，确实缺失才补问或停止，执行中更新按权威版本处理。
2. 独立来源样本生产观察后，再检查接纳、冲突、未知与展示引用；不得由输入条件自动生成“全部满足”的Evidence。历史记录不可自动支持当前展示。
3. 有合法动作时继续、已有合格结果时完成；资源耗尽、取消、来源失败或无进展时以实际原因停止。预算按run累计且跨run隔离，换阶段或候选不得重置。
4. 已提供的修改、刷新、取消、重新加载等用户操作必须到最终权威State；旧请求晚到不可覆盖新请求，刷新失败不可恢复旧成功。只覆盖产品已承诺的并发与恢复行为。
5. 实际流程先产出artifact，再交既有Evaluator独立诊断；测试期望来自输入和独立来源样本，分别报告执行、诊断和未评估维度。模型替身只证明内部执行契约，不证明真实模型质量。
6. 同一共享契约变更列出受影响的Runner、Web及其他实际调用方，在同一切片修改、验证并退役被替代路径；测试按行为命名，不按H001等caseId组织产品分支。

## 每种测试证明什么

### 模块、集成与模型选路的分工

改变工具契约、动作资格、Context或完成规则时，切片计划必须列出受影响的既有主测试、需要迁移/删除的旧断言，以及对应artifact评价维度。模块测试证明规则；实际入口集成证明规则被接入；真实模型诊断证明该次模型能否理解工具并作合理选择。任何一层通过不能替代另外一层，也不要求为每项普通修改重复运行全部层次。

需要隔离模型选路与网站变化时，可复用生产composition安排“真实模型+固定来源响应”的有界混合诊断。它仍是付费模型调用，需要独立授权/预算，不进入默认离线测试。记录来源响应是Synthetic还是Replay；固定环境未覆盖的合法调用标诊断覆盖缺口，不冒充外部来源失败。评价任务条件、合法动作、证据利用与终态，不能用唯一预设动作顺序或特定站点作为答案。

调查顺序可以不同；对互相独立的合法读取验证共同结果契约，而不是穷举排列或比较随机ID。有时序意义的刷新、冲突和取消另测，不能为了顺序等价放松证据适用性。

已知故障的回归先在未修业务代码上运行并保存失败依据；确认失败发生在目标契约断言，而非样本、替身、类型或环境错误。至少保留相应正常对照，避免“无论实现如何都会失败”的测试。涉及批处理/聚合时，按实际风险检查单批与跨批、合法顺序和不同候选/来源的隔离，不只使用恰好一批的成功样本。

测试预期写用户承诺，不断言当前错误输出。修复验证体系的切片可以明确交付仍失败的业务回归，但必须进入默认`npm test`，不得用skip/todo、反转断言或排除文件掩盖；单独列出已修的验证缺陷与待修的产品缺陷。默认套件通过仅代表列明的离线行为，不构成模型选路或Live验收；已知未覆盖项必须保留。

| 模式 | 证明范围 | 不证明 |
|---|---|---|
| Unit / Adapter Mock | 参数、解析、状态/错误分支、授权与幂等 | 真实页面DOM与网络行为 |
| 真实浏览器 + 本地Fixture | 实际控件操作、异步状态、等待和恢复 | 当前网站可访问或可预约 |
| Replay | 脱敏真实响应的回归 | 当前站点状态与库存 |
| 真实模型 + 固定来源响应 | 本次模型对工具/Context/失败反馈的理解与受控调查质量 | 当前真实网站可访问、实时库存、长期模型成功率；不属于纯离线Mock |
| Live Read-only | 此次环境下连接、门店、请求条件与空位 | 真实提交成功或长期可靠性 |
| Controlled Live-write | 授权范围内真实写入及验证/清理 | 未测平台或任意网站自动化 |
| Embedded-postgres integration | PGlite的SQL/事务/恢复 | 真实PostgreSQL部署 |

首次接入没有Replay样本时明确记录缺口，先做受控只读观察，再按来源政策建立脱敏回归。合成HTML不命名为Replay。未来Golden目录项不自动成为当前Stage必过项。

## 关键行为

- 优先测试外部行为与状态转换，不重复等价私有分支，不因覆盖率保留旧实现测试。
- 未授权Commit、重复提交、错误候选/Attempt Evidence导致的成功均为0；`OUTCOME_UNKNOWN`禁止再次提交和换店。
- 新Proposal必须有新Authorization；跨用户Case、Takeover和Profile访问被拒绝；Projection不改变权威State。
- Browser条件修改后观察新请求对应结果；旧slot、加载中、challenge或未知页面不能形成AVAILABLE/UNAVAILABLE结论。
- 检测到控件、尝试操作、观察到生效分别记录；未实测为未验证。静态只读限制不冒充副作用实测计数。
- 确定性时间逻辑用Fake Clock；浏览器deadline另做有界异步验证，空waitFor不证明浏览器行为。

## 测试维护与退役

- 新增自动化测试前搜索同一行为的既有覆盖，优先扩展所属测试。说明新增测试能捕获什么现有测试漏掉的失败；无需为每个模块、函数或改动机械新增测试文件。
- 同一输入、同一执行路径、同一失败后果只保留一处主覆盖。等价数据变体使用带案例名称的参数化断言；不同故障机制不要为了降低数量塞进一个大测试。
- Unit负责规则与边界，集成测试负责规则接入、事务和真实协议；跨层重复只有在能捕获不同故障时保留，不把Unit的全部组合复制到Harness/Web。
- 替换实现或修复缺陷时，同一改动中检查相关旧测试：更新仍有效的行为断言，删除被替代路径及重复回归，保留真实状态所需的迁移验证。新增缺陷用例优先并入所属行为测试，不无限追加独立回归文件。
- 不绑定无契约意义的私有调用次数、文案、CSS断点或源码形状；时间/重试预算、Secret隔离、授权和副作用次数属于真实契约，应保留。脆弱测试修复等待与观察条件，不通过重试或放宽断言掩盖失败。
- 默认套件只收当前产品及其维护所需的离线行为测试；浏览器、冻结探针和Live按现有独立入口运行，不为减少报告数字隐藏当前必需测试。
- 涉及测试变更的交付简记新增/合并/删除及覆盖去向，关注重复setup、运行耗时、偶发失败和维护成本。数量与覆盖率不是增长目标，也不设强制删除配额；只审查当前受影响范围，不每次全仓盘点。

## 运行边界

普通测试不加载.env，不调用付费模型或外部生产服务，不创建真实预约。`test:browser:fixture`只启动本机浏览器和本地Fixture，不读取站点Cookie或个人profile；缺少浏览器时明确失败，不伪装为通过。

真实PostgreSQL仅使用授权专用测试库和`PRAXIS_ALLOW_TEST_DATABASE_WRITE=1`；Live/付费实验还需对应开关与用户授权范围。Controlled Live-write不能在CI运行，完成后记录取消/清理。环境开关不等于授权。

报告通过、失败、未运行、不适用及原因，分别列运行模式；不能证明真实结果或清理失败时明确保留限制。
