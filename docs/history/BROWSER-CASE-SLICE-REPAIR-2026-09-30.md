## H003 first failure and minimum change

The saved TableCheck artifact starts with seven browser operations before model action. Date and party controls are both present. On the first party open, the model observation contains only options 1–8; the listbox region's full text mentions 9, 10 and 10+, and the region is marked scrollable. The model then advances the month and selects Oct 2 before reopening party. This is a legitimate response to partial option visibility, not proof that the initial open was purposeless. With the prior unconditional `WAIT_FOR_CHANGE` after each click, five actions cost four operations each; operation 24 was the final 10-person click and no wait or readback could follow. The Adapter returned `UNKNOWN`, not a no-slot result.

The shared `BrowserTaskExecutor` now snapshots and observes immediately after an action. It uses the observed URL/text/control-state change for progress and skips the extra wait only when a change is actually visible and a chosen option is confirmed. If there is no change or an option remains unconfirmed, it performs the prior bounded wait followed by a new snapshot and control observation. The next model decision may reuse only that post-action observation of the current snapshot. `controlsChanged` includes visible/disabled transitions as well as value/selection. No browser action is treated as availability: the Adapter's exact request and source slot checks are unchanged.

Before a proposed browser action, the Executor also requires enough remaining operations for that action plus a new snapshot and (when supported) control observation. If insufficient, it returns an explicit operation-budget stop **without clicking**. This prevents a final unverified click; it does not by itself make the read successful or add budget. The existing unit budget scenario now verifies that the source receives zero clicks at this boundary, while the five-action Adapter path still completes.

The same real-source trace also showed `10+ guests` incorrectly offered as an exact `CHOOSE_OPTION:PARTY_SIZE` for ten. The shared authoritative match now rejects a label containing a plus or multiple quantities before accepting the exact numeric value. The existing final action guard and model action hints both use this matcher. It still accepts an exact `10 guests` control.

The existing browser-read Skill now tells the model to scroll the observed owning list region and re-observe when a combobox exposes only some options. Region prose cannot stand in for an option reference, and the guidance does not impose a date-first order. This is a prompt instruction for task continuity; its effect on the real model has not been measured.
