## 需要修（按优先级）

1. **C3：持续变化的页面可能永远判为"仍在加载"（Live 前修）。** 稳定条件要求整页 DOM 连续 300 ms 无变化（含属性变化）。轮播、计时器、倒计时会让页面永远达不到；此时快照标为 PENDING，完成判定一律不通过，即使结果已经在页面上。另外，原来页面一有变化就继续，现在每个非 WAIT 动作都要等到稳定，至少 300 ms、最多 4 秒，整单 500 秒上限内的余量会变少。建议：无网络请求、无忙碌标记，且可见文字与可交互状态在相隔 ≥300 ms 的两次采样中不变，也视为稳定；补一个"结果已出、旁边轮播一直在动"的 Fixture。Live 报告里统计每次运行的 `PAGE_STILL_LOADING_WITHIN_BOUND` 次数和动作后等待总时长。
2. **C0b/C0c：读取中途触发保留量时，同批已完成的门店结果被丢弃（Live 前修）。** 一次查位最多 3 家；第 1 家已拿到合格时段、第 2 家读到一半触发保留量，整批抛错，第 1 家结果不入状态。C0c 之后，这会直接变成"诚实结束、无结果"。改法：触发保留量时，提交已完成门店的结果，未完成的记为带原因的 UNKNOWN，再交回 Agent。补正反例。
3. **C6a 补充：一家店关门就会结束整个读取（P1-F 前修）。** 现在的条件是"所有已查门店都显示该时段不营业"。只查了 1 家且它当天休息，条件就成立，而且校验器随即拒绝所有新的搜索、事实读取和查位，Agent 只能结束。这把"当地明显不在营业时段"变成了"第一家店恰好休息"。建议：至少 3 家已查门店都有明确的不营业证据、且没有任何一家营业或未知，才触发；或者只把它作为"允许结束"的选项，不禁止继续读取。只影响原版实时 h005，不影响 P1-E 的三个已知可行变体。
4. **ADR-0039 原文被改写。** `aab7485` 把"Retained limits"段最后一句（"Detecting an obviously out-of-business-hours … remains unimplemented …"）改成了新的表述。Accepted ADR 只能追加。恢复原句，状态变化只写在补充段。ADR-0036、ADR-0038 的改动都是追加，没有问题。
5. **执行器的提示语误导模型等待（小）。** 点击后页面无可见变化时，progress 写"result is still not observable … or WAIT"。#12 的分类链接其实已经在页面上，模型照字面选了 WAIT。改成"该动作没有产生可见变化；从当前目标中选能推进目标的一个，结果确实在加载时再等待"。
