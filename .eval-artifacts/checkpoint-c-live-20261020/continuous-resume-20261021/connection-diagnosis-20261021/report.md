# TableCheck 搜索页连接差异：只读诊断

结论：当前 TUN 排除列表有已确认的 DNS 地址覆盖缺口。当前配置采用固定 AWS CIDR，能覆盖网段内的地址变化；这不足以称为已解决任意动态 DNS 变化。未修改网络配置，0 模型、0 正式 Live。

| 对照 | 地址 / 路径 | 同一搜索 URL 的结果 |
| --- | --- | --- |
| curl 普通解析，关闭显式代理 | 52.68.109.188 / utun84，源172.18.0.2 | TLS SSL_ERROR_SYSCALL，HTTP0，0响应字节 |
| 全新 Playwright 原生文档导航 | 同一搜索 URL，仅允许文档GET | ERR_CONNECTION_CLOSED |
| 相同curl，仅固定为另一个当前DNS地址 | 54.178.173.154 / en0，源192.168.1.104 | HTTP200，Map Search - Japan，99089字节 |
| 本机应用浏览器 | 同一完整搜索URL；远端IP未捕获 | Showing 1–20 of 653，CADRAN等结果可见 |
| 失败IP的en0作用域检查 | 52.68.109.188 | not in table；HTTP对照未派发 |

当前DNS另有54.178.32.17，也在54.178.0.0/16内；52.68.109.188不在任何现有排除CIDR中。现有列表中的52.192.0.0/11不覆盖52.68.*。因此“昨天覆盖了动态IP”仅能指预列网段内变化，并不是新网段出现后也会被自动纳入。

浏览器可能选择了不同/缓存地址，这能解释浏览器可用而新进程失败，但本次未观察到其远端IP，不把该解释当已直接证实。由于en0作用域缺路由，没有完成同一52.68.109.188的en0 HTTP对照，不宣称已经排除该IP服务器侧差异。应用浏览器另有地图服务错误，但搜索列表确已出现，不能将地图问题混为搜索无结果。

诊断与已停批结果分开：较晚的成功页面不追改两次ENV_FAILURE，也不生成本不存在的正式Runner result、find_vacancy或独立查位GET。后续稳定修复需覆盖DNS变化和实际直连出口的持续可用性；只再补一个CIDR仍是静态覆盖。
