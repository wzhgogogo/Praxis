# 店名解析基准：按名称在 Tabelog 和 TableCheck 上找到同一家店有多难

状态：用户 2026-10-19 提出。第 1–3 项现在可以离线做；第 4 项要等网络恢复（TableCheck 不再 503、Tabelog 不再"访问集中"），并且用户批准预算后才跑。开始前 `git pull --ff-only`。

## 为什么做

Google 候选大多只有名称。查位前，系统要先在 Tabelog 或 TableCheck 上按名称找到同一家店。P2-0 和第一阶段中这一步经常失败，但原因混在一起：

- VPN 导致 TableCheck 卡住；
- Tabelog 返回"访问集中"页面；
- 名称写法不同；
- 真的不在该平台上。

这个基准把"按名称找到同一家店"单独拿出来测量。它既决定 P2-2 要不要继续投入名称解析，也是检验浏览器 Agent 通用能力的一个侧面基准：在陌生网站上，按给定线索找到一个特定实体，并证明找对了。

## 1 构建有标准答案的样本集（离线，0 网络、0 模型）

**标准答案的来源**：Google 候选的官网字段直接指向 Tabelog 门店页或 TableCheck 门店页时，我们就知道正确答案（门店 ID）。

1. 扫描已有产物：22 次校准运行、P2-1 各轮探测、P2-0 运行。收集所有满足以下条件的 Google 候选：
   - 官网字段是 Tabelog 门店页（`/A\d+/A\d+/\d+/`），或 TableCheck 门店页；
   - 有 Google 名称、地址、电话、坐标。
2. 按门店 ID 去重，记录 Google 名称（原样）、地址、电话、坐标、地区，以及作为标准答案的门店 ID。
3. **抽样**：
   - Tabelog 约 30 家、TableCheck 约 10 家；
   - 覆盖不同地区（涩谷、银座、神乐坂、吉祥寺、中目黑等）；
   - 覆盖不同名称形态：纯英文、含分店后缀如 "(Shibuya)"、日文、含"Sushi/Restaurant"等泛称。
4. **对照组**：另选约 10 家官网是自有域名、Instagram 或没有官网的 Google 候选。它们没有标准答案，只统计结果分布；判对判错由复核者人工核对。
5. 冻结样本集，记录 SHA，提交给复核者审核，**复核者批准后才能运行**。

## 2 被测方法（与生产一致，不改生产逻辑）

对每个样本，**隐藏官网字段**，只给生产名称解析流程 Google 名称、地址、电话、坐标，按现有流程去找：

- **方法 A**：生产现有的名称解析流程（含已修复的繁忙页识别，见 P2-2 复核补充），原样运行。
- **方法 B**（可选，仅当 A 的结果不好时）：同一份输入，让浏览器 Agent 在来源站点上自主搜索（可改写名称、换语言、用地区筛选），最后由代码按现有身份规则核对。这一项测的是 Agent 的通用浏览能力。

两种方法都**只读**：不打开预约表单，不点时段。

## 3 指标（在 `src/eval` 中计算，由评测器独立判定）

| 指标 | 含义 |
| --- | --- |
| 找对率 | 返回的门店 ID 与标准答案一致，并通过身份规则 |
| **找错率** | 返回了另一家店并判为同一家。**最严重，目标为 0**；出现即为 S0 级问题，立即停止 |
| 不确定率 | 找到了但身份核对没通过（细分原因：繁忙页、缺地址电话、名称只部分一致） |
| 没找到率 | 搜索 0 结果，或结果中没有标准答案 |
| 失败分类 | 繁忙或限流、超时、0 结果、多结果无法区分、跳到其他页面 |
| 耗时 | 每家的耗时，及其中位数和最长值 |
| 模型调用 | 每家的模型调用次数 |

按名称形态和地区分组报告。

## 4 运行（网络恢复且用户批准后）

- **预检**：来源可达性检查通过（TableCheck 200、Tabelog 非繁忙页），否则不跑。
- **节奏**：同一来源相邻两次解析之间至少间隔 30 秒；遇到 503 或繁忙页，暂停 10 分钟后继续；同一天累计 3 次就停止，第二天再跑。
- **预算（待用户批准）**：
  - 方法 A：约 50 家 × ≤ 3 次模型调用 ≤ 150 次；
  - 方法 B：只在需要时跑，≤ 100 次；
  - 不计入第二阶段 Live 次数，计入阶段模型调用总额。
- 每家保存原始页面摘要和身份比较记录，便于复核者抽查。

1. 按名称在 Tabelog 和 TableCheck 上找到同一家店，本身难不难？难在哪里？是名称写法、平台搜索能力、限流，还是根本不在平台上？
2. 对 P2-2 的含义：名称解析值不值得改进？哪些改进最有效（名称规范化、换语言、用地址或电话搜索、Agent 自主搜索）？
