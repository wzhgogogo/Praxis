# 入口停顿重试：原生取消语义验证，粒度待确认

Status: draft / local feasibility only，尚未接入生产自动重试。2026-11-09 Asia/Shanghai。用户要求只在连接已建立后5秒无数据重试、4xx/5xx不重试、最多1次、先abort旧请求并记录重试次数。

本轮没有源站GET、模型或Live，没有改产品/Guard/网络/时限。使用当前安装的Playwright和真实本地Chromium+原Guard默认静态原生传输，本机接收端提供一份200且已发送初始正文的CSS，随后停止正文。

## 取消机制的实测

- 资源已route.continue后再route.abort会报ROUTE_ALREADY_HANDLED。
- AbortSignal取消goto返回AbortError，但等待150ms后服务端旧响应仍未关闭；不能把这当作成功abort。
- Page.stopLoading后服务端旧响应close，浏览器Network.loadingFailed为ERR_ABORTED；之后才再次打开同一入口。服务端记录证明旧响应关闭先于第二次CSS请求，CSS总请求2次，第二次入口完成。
- 第三步重开的是整次入口，因此入口文档和其它已完成静态资源也会重新发出请求，不等于单个CSS请求的原地重试。没有把该实验直接接入生产。

见native-cancel-result.json和原日志。这个探针用短诊断延迟验证取消顺序，不是生产5秒/20秒门禁通过。

## 触发条件实测

另一组本地真实Chromium检查：SUCCESS_STALL(200、已收到正文后停顿)识别为可恢复候选；HTTP403、HTTP500、没有响应头/连接未知、持续收到正文均不可恢复。每个检查仅1次资源请求，未执行自动重试。持续正文收到9个data事件，没有按总用时误判。

见idle-conditions.json。该条件探针使用200ms局部测试阈值，生产5秒尚未实现；不把缩短的条件验证说成真实5秒恢复或源站成功。没有连接/HTTP状态证据的旧Live未完成CSS不得自行推定为可重试。

## 必须先确认的实现粒度

现有原生继续接口没有继续后独立取消单个请求的能力；goto取消只取消等待。已实证的简单恢复方式是中止整次入口再重开一次，这比用户的单请求表述范围更大。已经向用户发出选择：接受整次入口重载一次（保留原生下载），还是必须只重试卡住的单个资源（需要另外设计传输/取消路径）。这是运行时接口限制导致的粒度决策，不是新增安全审批。没有假定用户沉默表示接受。

若选择入口重载，计划边界：仅首次入口、已确认成功响应与5秒无正文进展；已出现4xx/5xx、POST或交互时不重载；先确认旧请求终止、一次重载、原入口总20秒不变，每次attempt/abort/retry原因录入，全部请求重新过同一个Guard。需要真实本地覆盖连续进展、状态错误、第二次再挂、取消、预算和录制，不能由本轮可行性实验替代。

当前生产源码未修改，所有真实失败原件保留。等待粒度决定后才能完成实现；本轮模型/GET/Live均0，额度仍GET378/486、Live29/47、模型784/1600，留出18Live/108GET不动。未推送。
