# 对话 B：G3 长批次（补充指令）

用户希望 G3 一次跑得更远，不必每个小步骤都停下等复核。以下补充上一条 G3 指令，时间一律用维也纳时间（CET，UTC+1）。

## 目标

**让 Agent 观察页面并行动，而不是用代码限制它。** 网站适配器行数不再作为验收条件，只记录参考。验收以 `PRAXIS_G2_REQUIRE_PASS=1 npm run test:dom-change` 和真实任务行为为准：私有标记改名后，Agent 仍能完成任务或如实报告，不产生错误声明。

## 范围（按顺序做，中间不停）

1. **G3：Tabelog 查位路径。** ADR-0046 清单中的 OBS-13、14、15、18、19、21、33，以及它们依赖的共享浏览器部分（OBS-08 日历 day 结构、OBS-09 class 判断选中状态等）。日历日期状态、时段、人数/时间控件、列表页店名与地址、busy 区域，全部改为：Agent 观察可见文字、label、ARIA → 引用 → 代码核对。find_vacancy 响应保留为数据证据，格式变化发出 `SOURCE_STRUCTURE_CHANGED`。已知选择器可以保留为加速路径，失配时回到观察，不能因此失败。
2. **G3c：套餐、价格和事实读取改用 G1 的通用方式。** OBS-22、23、24（Tabelog 套餐、价格、信息表）、OBS-29、30（TableCheck 菜单分区、菜单价格）、OBS-35、36（事实读取复用的私有字段）。做法：读可见文字 → 模型选原文 → 代码核对逐字出现在同店本次页面上；需要比较的数字（价格）由代码从被引用的原文中解析，不由模型给出。旧 HARD 判断的输出如有变化，先说明原因并取得复核；不得为了方便降低核对。
3. **不在本批：** 身份字段（OBS-20、31，对话 C 负责）；TableCheck 查位（OBS-25、26、27、34，等第一次 Live 录到有时段的日历后做 G3b）；对话 C 的详情排序改动涉及的 `tabelog-browser-availability.ts` 和 `tabelog-entity-resolver.ts`（如需改动先停下报告）。

## 工作方式

- 每完成一组（例如“日历日期状态”“时段”“列表页”“套餐价格”），先红灯后绿灯，五门禁全绿，**提交并推送工作分支，在报告中记一笔，然后继续下一组，不停下等复核。**
- 只有遇到以下情况才停：门禁修两次仍红；出现错误声明（S0 类）；需要放宽身份、Guard 或授权规则；需要改动对话 A/C 的文件或抢占他们的版本；需要递增 State/TaskDefinition（先报告再改）；需要真实调用。
- G3 删除私有逻辑时，对应测试由你删除或改写，并在报告中逐项列出；其余测试由对话 A 审查，不要相互改对方的文件。
- 真实模型 0；不读取 `.env`；不读取 `answers*.json`。
- 全部完成后停下，报告每组的红绿、G2 REQUIRE_PASS 结果、五门禁、行数（参考）、仍保留的私有依赖及理由。不合入 main，等复核。
