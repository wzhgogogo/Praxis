# Tabelog Public Read

Use only the supplied public Tabelog search and restaurant pages. Open only observed public links relevant to the stated objective: restaurant results, listing categories, query-filter removal, and result pagination. Treat challenge pages, external reservation providers, login, and booking paths as stop conditions; do not bypass a challenge or follow an external provider.

Checkbox/range changes require an explicit source-owned query contract; GET form structure alone is not permission. When a public Tabelog availability surface has observed date and party controls, set only the authoritative values and re-observe before reading explicitly available time controls. Do not treat rankings, reviews, restaurant names, or prose times as identity or availability evidence.

Never submit a reservation, enter personal details, or navigate outside the allowed Tabelog origin.

On an observed public listing search input, Discovery may fill only the supplied retrieval expression. Re-observe the current page and use an observed public query control or current result; never use the field to change the area, HARD criteria, date, party size, or time.

When Discovery explicitly asks to broaden a sparse keyword query, choose a relevant category from the site's observed Search by category links and use its keyword-removal link if necessary. The observed `All` link in Search by category opens the category panel; use its permitted CLICK action, then re-observe the category choices. Do not guess that an unlabeled button opens this panel. Category links may preserve the old keyword. Keep the same area. A category is only a discovery lead; it does not establish that any restaurant satisfies a HARD criterion. Follow only an observed next-results link for pagination.

The source may label nonstandard calendar controls as `Date YYYY-MM-DD` and guest controls as `Guests N`. These labels are derived from the observed element, not the task goal. Use CLICK_AUTHORITATIVE with DATE or PARTY_SIZE for the exact requested value. Selected query controls and visible time choices alone do not establish bookable inventory.

Wait for a visible selectable date and an enabled visible guest control on the current calendar. Hidden future-month dates and disabled guest controls do not make the query ready. If the source reports that the current guest query cannot be adjusted, stop with a source-control limit; do not infer no availability for the requested date.

The observed English calendar time buttons navigate into booking forms. They are evidence-only; do not click them to inspect availability. Source-owned verification reads only captured public vacancy-query responses with matching merchant/date/party/time.
